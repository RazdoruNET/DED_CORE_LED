# Протокол модуля с DED CORE V4

Модуль — клиент точки доступа ядра. Он не поднимает собственную сеть в рабочем
режиме и не требует настроек на стороне ядра: ядро уже рассылает телеметрию всем
подключённым клиентам WebSocket.

## 1. Кадр телеметрии ядра

Ядро рассылает кадр (порт 81, `{"event":"message","data":{…}}`). Модуль читает
только поле `card`; остальные (обороты, углы, серва, WiFi-состояние) игнорирует.

```json
{
  "event": "message",
  "data": {
    "card": 0,
    "rpm": 3500,
    "max_rpm": 12000,
    "angles": [[1200.00, 10.00, 0, 0, 0], "…"]
  }
}
```

| Поле | Смысл для модуля |
|---|---|
| `card` | активная карта, **0…2**: 0 — карта 1, 1 — карта 2, 2 — карта 3 |
| `select_cart` | выбранная карта в интерфейсе, **1…3**; для индикации не используется |
| `rpm`, `max_rpm` | обороты; модулю не нужны и не читаются |

`card` — это `active_cart` ядра. Переключение карты кнопкой на блоке или
командой `{"event":"cart","data":{"cart":N}}` меняет `active_cart`, и ближайший
кадр приносит новое значение. Модуль не повторяет логику переключения: он
показывает то, что ядро уже применило.

### Отображение

```
card 0 → GPIO 18 (светодиод карты 1)
card 1 → GPIO 17 (светодиод карты 2)
card 2 → GPIO 16 (светодиод карты 3)
```

Любое другое значение, в том числе отсутствие поля, гасит все светодиоды.
Горит всегда ровно один выход: перед зажиганием нового карта-светодиода
остальные принудительно гасятся.

### Свежесть кадра

Признак «линк есть» — кадр не старше 3 секунд. Ядро рассылает телеметрию
непрерывно, поэтому молчание дольше этого означает потерю связи: все
светодиоды гаснут и ждут кадров.

Дополнительно включён WebSocket-heartbeat (ping 15 с, ожидание pong 3 с, две
пропущенные попытки): без него разрыв по радио оставляет TCP-соединение
«открытым», и модуль считал бы старую карту актуальной.

## 2. Сопряжение

Пароль точки доступа ядра уникален для блока, хранится в NVS и не отдаётся ни по
HTTP без `X-Device-Key`, ни в кадре телеметрии. Модуль, который к ядру ещё не
подключён, узнать его не может — поэтому ядро по команде из приложения открывает
отдельное окно сопряжения.

### Сеть сопряжения

1. Владелец открывает окно из приложения: `POST /module/pair/start` с ключом
   устройства (`X-Device-Key`).
2. Ядро на 90 секунд поднимает открытую сеть `DED_PAIR_<4 hex>` (хвост MAC блока)
   вместо основной точки доступа. Телефон на это время отключается от блока.
3. Модуль сканирует эфир, находит сеть с префиксом `DED_PAIR_`, подключается к ней
   и запрашивает `GET http://192.168.4.1/module/pair`.
4. Ядро отвечает и через 3 секунды возвращает основную точку доступа.
5. Модуль сохраняет параметры в NVS и перезагружается.

Ответ ядра:

```json
{
  "event": "module_pair",
  "data": {
    "ssid": "DED_BOX_V4",
    "pass": "уникальный пароль блока",
    "host": "192.168.4.1",
    "port": 81,
    "token": "<токен модуля>",
    "fw": "4.0.16"
  }
}
```

`token` хранится в NVS модуля и подтверждается при каждом подключении. Без него
ядро не присылает смену параметров сети, и модуль после смены пароля потерял бы
блок.

Если окно закрыто или запрос пришёл не из сети блока, ответ — `403`.

### Безопасность

* Сеть сопряжения открытая, потому что модуль до сопряжения не знает пароля.
  Окно открывает только приложение с ключом устройства: у привязанного блока без
  `X-Device-Key` запрос отклоняется.
* Маршрут отдаёт только параметры основной точки доступа, ключ устройства и
  данные ядра не отдаёт.
* Окно закрывается само по таймеру; после ответа основная точка доступа
  возвращается сразу.
* На время окна телефон владельца отключается от сети блока: ESP32 держит одну
  точку доступа.
* Автоматическое пересопряжение ограничено сохранённым BSSID точки сопряжения:
  чужая открытая `DED_PAIR_*` в радиусе не уведёт настроенный модуль на
  поддельный блок. Замена ядра — только через кнопку поиска в портале.

### Состояния модуля

| Состояние | Что делает модуль |
|---|---|
| Настроек нет | портал + попытка сопряжения каждые 20 с |
| Настройки есть, связи нет | повтор подключения каждые 20 с; через 60 с — поиск сети сопряжения **своего** ядра (по BSSID); после 10 неудачных стартов — портал |
| Связь есть | WebSocket к ядру, индикация карты |
| Кадров нет > 3 с | все светодиоды погашены |

## 3. Доверенный модуль

После подключения к WebSocket модуль отправляет подтверждение:

```json
{
  "event": "module_hello",
  "data": {
    "mac": "AA:BB:CC:DD:EE:FF",
    "fw": "1.0.0",
    "token": "<токен модуля>"
  }
}
```

Ответ: `{"event":"module_hello","data":{"trusted":1}}`. При `trusted: 0` модуль
продолжает работать, но смену сети от ядра не получит — нужен новый токен
(сопряжение).

### Смена параметров точки доступа

Когда владелец меняет имя или пароль точки доступа, ядро сначала присылает
доверенным модулям:

```json
{
  "event": "module_credentials",
  "data": {
    "ssid": "DED_BOX_V4",
    "pass": "новый пароль",
    "host": "192.168.4.1",
    "port": 81
  }
}
```

Модуль сохраняет параметры в NVS и сразу переподключается с новыми данными.
Через 1,5 секунды ядро перезапускает точку доступа, и связь восстанавливается без
пересопряжения. Пересопряжение остаётся запасным путём: если модуль был выключен
в момент смены пароля, кадр он не получит и найдёт блок только через
`DED_PAIR_*`.

## 4. Портал настройки

Точка доступа `DED_CORE_LED`, открытая, страница `http://192.168.5.1/`.
Подсеть портала (192.168.5.0/24) отличается от сети ядра (192.168.4.0/24): в
режиме AP+STA совпадающие подсети делают маршрут до ядра зависимым от порядка
интерфейсов.

| Маршрут | Назначение |
|---|---|
| `GET /` | страница состояния и настроек |
| `POST /save` | сохранить `ssid`, `pass`, `host`, `port` |
| `GET /pair` | запустить поиск сети сопряжения |
| `GET /led/test` | прогнать самопроверку светодиодов |
| `POST /reset` | сбросить настройки ядра |
| `POST /close` | закрыть портал |
| `GET /update` | обновление прошивки (логин `admin`, пароль из лога) |
| `GET /status.json` | состояние в JSON |

`status.json` в рабочем режиме:

```json
{
  "event": "status",
  "data": {
    "fw": "1.0.0",
    "link": 1,
    "core_ssid": "DED_BOX_V4",
    "core_host": "192.168.4.1",
    "card": 0,
    "led": 0,
    "frames": 15230
  }
}
```

`card` — активная карта (0…2, `-1` — данных не было), `led` — индекс горящего
светодиода (0…2, `-1` — все погашены).

Маршруты настроек отвечают только при открытом портале. Исключение — `/update`:
его регистрирует ElegantOTA, поэтому страница обновления доступна и после
закрытия портала (из сети ядра), но только с паролем обновления.
