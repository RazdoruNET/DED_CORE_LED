# DED CORE LED — модуль индикации выбранной карты для DED CORE V4

Прошивка ESP32 для внешней панели из трёх светодиодов в системе
**DED MOTO SYSTEM**. Модуль подключается к точке доступа базового блока
[DED_CORE_V4](https://github.com/RazdoruNET/DED_CORE_V4) как обычный WiFi-клиент,
читает номер активной карты (`card`) из кадра телеметрии WebSocket и зажигает
соответствующий светодиод.

Это переписанная версия модуля `DED_VISION_LED` (ядро DED BOX V2/V3). Старая
прошивка не может работать с V4: пароль точки доступа ядра больше не зашит в
исходники, а получение настроек шло через сеть `DED_RECOVERY`, которой в V4 нет.

## Что изменилось относительно DED_VISION_LED

| | DED_VISION_LED (V3) | DED CORE LED (V4) |
|---|---|---|
| Ядро | `DED_BOX_V2` с паролем из прошивки | `DED_BOX_V4`, пароль уникален для блока |
| Подключение | пароль вшит в `PROPS.h`, настройка через `DED_RECOVERY` | сопряжение из приложения блока (`DED_PAIR_*`) |
| Самопроверка при старте | последовательность с `delay()` в `setup()` задерживала запуск | в отдельной задаче, подключение к ядру не ждёт |
| Потеря связи с ядром | последняя карта оставалась гореть | все светодиоды гаснут |
| Проверка связи | текстовый `ping` на каждом шаге цикла, кратном миллисекунде | WebSocket-heartbeat: ping 15 с, ожидание pong 3 с |
| Bootloop | счётчик в NVS не работал (ключ длиннее 15 символов) | счётчик неудачных стартов, после 10 — портал настройки |
| Структура | Arduino-скетч, всё в `.h` | PlatformIO: `src/config`, `src/app`, `src/net` |
| Отладка | `Serial.print` в цикле | лог только по событиям, индикация в отдельной задаче |

## Железо

| Сигнал | GPIO | Примечание |
|---|---|---|
| Светодиод карты 1 | 18 | `card` 0 |
| Светодиод карты 2 | 17 | `card` 1 |
| Светодиод карты 3 | 16 | `card` 2 |

Выход — активный HIGH. Ток светодиода ограничивается резистором: пин ESP32
держит до 20 мА постоянно. Подробности — [docs/HARDWARE.md](docs/HARDWARE.md).

## Сборка и прошивка

```bash
pio run            # сборка
pio run -t upload  # прошивка по USB
pio device monitor # лог, 115200
```

Версия платформы (`espressif32@7.0.1`, Arduino core 2.0.17) закреплена так же,
как в DED_CORE_V4: на Arduino core 3.x не собирается WebSockets 2.4.
ESPAsyncWebServer и AsyncTCP взяты из ветки 3.x — её требует ElegantOTA 3.1.6.

## Первое подключение

1. Включите блок питания. Модуль без настроек поднимает портал `DED_CORE_LED`
   и начинает искать сеть сопряжения ядра.
2. В приложении DED CORE V4 откройте «Настройки» → «Модули» и нажмите «Найти модуль».
   Блок на 3 минуты поднимает сеть `DED_PAIR_XXXX`, закрытую WPA2-кодом.
   Код появится в приложении — запишите его.
3. Подключитесь к порталу модуля, введите код в поле «Код сопряжения»,
   нажмите «Сохранить код», затем «Найти ядро сопряжением».
4. Модуль находит сеть, получает имя и пароль основной точки доступа ядра,
   сохраняет их в NVS и перезагружается.
5. Дальше модуль подключается к `DED_BOX_V4` и к WebSocket ядра на порту 81.

Пароль точки доступа можно менять из приложения: ядро пришлёт модулю новые
параметры до перезапуска сети, модуль сохранит их и переподключится сам.
Пересопряжение нужно, только если модуль был выключен в момент смены или если
сменили само ядро. Блок выдаёт новый код на каждое окно, поэтому после замены ядра или если модуль
пропустил смену пароля, откройте окно в приложении и введите новый код в портале модуля. Пока линка нет, модуль пробует сопряжение каждые 20 секунд
(первые 60 секунд после потери связи — ждёт, вдруг это кратковременный сбой).
Автоматически он ищет только своё ядро — сеть сопряжения с сохранённым BSSID;
если блок заменили, запустите поиск из портала.

Ручной вариант — портал: подключитесь к `DED_CORE_LED` и откройте
`http://192.168.5.1/`, впишите имя и пароль точки доступа ядра. Пароль,
сохранённый ранее, в страницу не выводится: пустое поле означает «не менять».

## Портал настройки

Портал открывается, когда модуль не настроен, или после десяти неудачных стартов
подряд — так модуль с неверным паролем ядра не остаётся без доступа к настройкам.
Точка доступа `DED_CORE_LED` открытая, страница — на `http://192.168.5.1/`:
портал живёт в своей подсети, чтобы не пересекаться с сетью ядра.
На странице: состояние линка, активная карта и горящий светодиод, ручной ввод
параметров ядра, кнопка поиска ядра, проверка светодиодов и обновление прошивки.

Обновление прошивки закрыто паролем: он создаётся при первом старте и печатается
в лог один раз (`SETTINGS: пароль обновления прошивки: …`). Логин — `admin`.

## Поведение индикации

* При включении — самопроверка: все три светодиода разом, затем по одному.
  Она идёт в отдельной задаче и не задерживает подключение к ядру.
* В работе горит ровно один светодиод — номер активной карты из поля `card`.
  `card` в кадре считается с нуля: 0 — карта 1, 1 — карта 2, 2 — карта 3.
* Нет кадров дольше 3 секунд — все светодиоды гаснут. Горящий светодиод при
  молчащем ядре показывал бы карту, которую уже никто не подтверждает.
* Неизвестное значение `card` (например, из будущей версии ядра) гасит панель:
  лучше «нет данных», чем неверная карта.
* Проверить панель можно из портала кнопкой «Проверить светодиоды».
